# Task 1.2 — Command suite with goldens on TSB Neo

Date: 2026-11-10. Reference: released CRT `TSBneo_md_260228_disklike.crt` in VICE 3.10 x64sc, headless, PAL, emulated
1541 (true drive). Labels: [Certain] = run or read here; [Likely] = strong inference; [Guessing] = plausible, unchecked.

## Summary

- **21 scenarios, 44 checkpoints, goldens in `tests/golden/commands/` (1.3 MB).** They cover **117 of TSB Neo's 121
  keywords** and **all 76 BASIC V2 tokens**, counted with the tokenizer, not by eye (`tools/cmd_coverage.py`).
  [Certain]
- **The 4 keywords not covered:**
  - MAP needs EXT.MAP and is exercised by the MAP and MULTIMAP demos.
  - PENX and PENY wait for a light pen, which headless VICE has no input for.
  - SECURE hangs TSB Neo (finding 2).
- **Reproducible:** after capture, independent `check` runs passed 21/21 (once on the virtual drive, once on the
  true-drive 1541 after re-recording the two goldens that print the drive's own status text), alongside 43/43 demo
  scenarios. Deliberately corrupted goldens (screen byte, charset hash) are reported as FAIL. [Certain]
- `make test-commands` runs the suite in about 1 minute. `make test` stays fast (G0 boot, detector, cruncher check).
- **New tokenizer:** `tools/tsblist.crunch` reproduces TSB's tokenizer. It re-tokenizes 1966 of the 1967 corpus lines
  byte for byte, and predicted a real TSB tokenizer bug that was then confirmed in VICE (finding 1). [Certain]

## How it works

Each scenario is a short text program in `tests/commands/*.bas` (the header comment says what it covers):
1. The harness tokenizes it exactly as TSB would, pokes it to $0801, sets the end pointer and types `RUN`.
2. Scenario steps type keys, hold keys or type direct-mode commands, with the same checkpoint logic as the demo
   baseline: the display has changed, then stays stable, with no disk transfer, and BASIC is back in direct mode.

Scenarios are in `tests/commands.json`. Options new in this task:
- `bas`: the program file.
- `disk: "scratch"`: a fresh writable D64 made with c1541.
- `printer`: printer 4 emulated with the raw driver; every byte it receives is compared.
- `reu`: REU size in KB.
- `until`: a regex the screen must match before a checkpoint counts.

**What each checkpoint stores:**
- the same as the demos: screen text, matrix, colour RAM, bitmap, RAM charset, VIC registers, sprites, screenshot;
- **`vars.txt`**: every BASIC variable and array, decoded to *values* (floats also as their 5 raw bytes), never
  addresses, so the same program in Ultra (different string-heap addresses) produces the same text;
- **`sidregs.bin`**: the last value written to each SID register;
- **`printer.bin`**: the printer scenario's received bytes.
- A RAM charset that is a copy of the Commodore character ROM (MEM copies it to $E000) is **not** stored as bytes:
  `charset.rom.txt` holds the ROM range, the SHA-1 and the changed offsets, and the check compares hashes.
  `tests/no_rom_in_goldens.py` (in `make test`) fails if any golden holds a 2 KB block ≥ 75% equal to the
  character, BASIC or KERNAL ROM.

    make test-commands                                         # all 21, compare with goldens
    tools/demo_capture.py check --scenarios tests/commands.json --golden tests/golden/commands tsb_reu
    tools/demo_capture.py capture --scenarios tests/commands.json --golden tests/golden/commands <id>   # Neo only!
    tools/cmd_coverage.py                                      # keyword coverage

## Findings about TSB Neo itself

1. **Tokenizer bug: typing `ELSEOPEN3,3` stores ELSE as `NO ERROR` + "PEN".** [Certain: typed into TSB Neo in
   VICE; `tsb_editor/10_elseopen` shows `LIST` giving `100 ifathenprint1:no errorpen3,3`.]
   - Why: TSB tokenizes its own keywords first. ELSE becomes `$64` plus index 71, which is the letter "G".
   - The V2 cruncher then reads that "G" plus the following "O" as the V2 keyword GO ($CB).
   - TSB decodes `$CB EOR $8F = $44`, which is index 68, NO ERROR.
   - Writing `ELSE OPEN` avoids it. NEO-BLISTER line 4685 holds the correct bytes, so that line wasn't typed as it lists.
   - **For Ultra:** its tokenizer must give the same bytes as Neo's, bug included, or the same keystrokes give a different program.
2. **SECURE hangs TSB Neo** in every form that parses: `SECURE 0`, `SECURE ON`, `SECURE OFF`, with or without a
   MOBCOL (ex-DISAPA) line in the program. The screen switches to multicolour text and BASIC never returns. [Certain in
   VICE.] The disk build keeps SECURE. The source shows it searching for the DISAPA token and patching bytes. It is
   left out of the suite: a golden of a hang can't be compared. **Proposal: Ultra drops SECURE or makes it an error;
   for you to decide (task 1.5 is a good place).**
3. **A LOAD inside a program restarts the program at its first line, with variables kept**, including TSB's
   `LOAD name,dev,0,addr`. This is V2's chaining behaviour, and it's why the corpus always writes
   `IF A=0 THEN A=1:LOAD …`. [Certain.] Ultra must keep it.
4. **COPY and HRDCPY dot bytes vary between runs.** About 190 of 11,624 printer bytes differ, all of them graphic dot
   bytes ≥ $80. The text and control bytes are identical every time. [Certain.] Cause unknown; maybe an interrupt during
   TSB's character-ROM read [Guessing]. The printer compare therefore checks text and control bytes exactly, and dot
   bytes only as "a graphic byte" (`printer: "no-dots"`). Worth a follow-up before G4.
5. **Syntax that differs from Simons' BASIC** (what I had to learn; all [Certain] from runs):
   - CALL jumps (no return; END PROC after it errors), while EXEC calls.
   - INSERT draws a frame from a 9-character string; PLACE is a function, and `PLACE 0` lists arrays.
   - INST loads the DOS Wedge; RETRACE prints the version ("ad23 / 2.60228").
   - FETCH needs RETURN; `ON ERROR:` takes a statement; binary literals need 8 or 16 digits.
   - AUTO is `AUTO start,step`; KEY needs arguments.

## Harness correction found during this task

The harness passed `-busdevice8` to VICE, which made VICE's **virtual** IEC device answer instead of the emulated 1541
(status `73,VIRTUAL DRIVE EMULATION V3.5`). Removed. Now `73,CBM DOS V2.6 1541`. [Certain.] The 43 demo scenarios were
re-run on the true drive:
- **SHOW DRIVES now works.** Its "fails on Neo" result came from the virtual device.
- MAP.DMO needed a checkpoint condition.
- SID traces now keep only states that last 2 frames or more.

Details are in the correction note at the top of reports/1.3-demo-baseline.md.

## What will differ in Ultra by design (for G4)

These goldens hold Neo's values where Ultra is *meant* to differ. G4 must mask or translate them rather than count them as failures:
- the boot banner (30719 vs 51199 BASIC BYTES FREE), visible in `tsb_session` (stop, cont, cold, final), `tsb_editor`,
  `tsb_hires`/`tsb_multi` final (the text screen behind the picture);
- `DISPLAY` with MEM on (`tsb_mem` prints 52224 = $CC00; Ultra's MEM screen is under I/O). Open point for task 4.3: should
  DISPLAY return the real new address or a compatible $CC00?
- anything decoded by address in `screen.txt` headers ("screen $C000", "bitmap $E000"). The binary parts compare the
  *content*, wherever the VIC points.

`FRE()` is only ever printed as a difference (0), so it doesn't depend on the memory size.

## Limits

- One run per command family, not every parameter combination. Error paths are covered by `tsb_errors` and TSBDEMO's
  error pages (demo baseline), not per command. [Certain]
- Not exercised:
  - MAP (needs EXT.MAP; covered by the MAP and MULTIMAP demos);
  - PENX/PENY (light pen);
  - SECURE (hangs);
  - X! with a real extension (covered by NEOBLISTER and EXTINSTALLER);
  - the tape device; a second drive;
  - JiffyDOS (an open question in the plan).
- Interactive timing (INKEY, ON KEY) is checked by result, not by frame. A slower Ultra still matches.
- VICE only; no real hardware. [Certain]
