# Task 1.3 — Demo baseline on TSB Neo 2.60.228

Date: 2026-11-10. Reference: released CRT `TSBneo_md_260228_disklike.crt` (Magic Desk) in VICE 3.10 x64sc (macOS SDL
build, headless via `SDL_VIDEODRIVER=dummy`), PAL, 1541 with true drive emulation, `corpus/tsbneo_260228.d64`
attached read-only.

> **Correction (10 Nov, during task 1.2):** the first version of this baseline did *not* run on the emulated 1541.
> The harness passed `-busdevice8`, which turns on VICE's virtual IEC device, and that device answered instead of
> the true-drive 1541 (the drive status read `73,VIRTUAL DRIVE EMULATION V3.5`). The flag is removed. All 43 scenarios
> were re-run on the real 1541 emulation (`73,CBM DOS V2.6 1541`) and the goldens updated. What changed: SHOW DRIVES now
> works (its failure was a virtual-drive artifact); MAP.DMO's first checkpoint needed an explicit condition (it had
> fired during the slower true-drive load); SID traces now keep only states that last ≥ 2 frames, because a single-frame
> state depends on load timing. All other goldens were byte-identical on the true drive. [Certain]
>
> **Also corrected:** 9 `charset.bin` goldens (COLORCOMBI, DESIGN3, OBLIQUE) were copies of the Commodore character
> ROM, which CLAUDE.md forbids in git. They are now `charset.rom.txt` (ROM range, SHA-1, changed offsets only), compared
> by hash; `tests/no_rom_in_goldens.py` guards this. The old files are still in the history of commit 8611100. Confidence labels: [Certain] = observed in this run or read in the source; [Likely] = strong
inference; [Guessing] = plausible, not checked.

## Summary

- The disk holds 72 directory entries: 4 separators, 2 system files (TSB loader + TSB.NEO), 4 TSB extensions,
  6 EXT.* extensions, 34 demos, 5 tools, 17 data files. [Certain]
- All 39 BASIC programs (34 demos + 5 tools) were run as 43 scenarios (TSBDEMO has 4 menu paths; IMG VIEWER and
  CHECK-DETECT have 2 each; SHOWIMAGESINREU runs chained after WRITEIMAGES2REU). [Certain]
- 43/43 reach every checkpoint, and a second independent run matched the goldens byte for byte (43 PASS, identical
  frame counts). A deliberately corrupted golden byte is detected (FAIL). [Certain]
- **3 programs do not work as intended even on TSB Neo** (their goldens record the Neo behaviour, error included):
  DO-TEST.DMO, OLD-AT.TSB, and IMG VIEWER.DMO without an REU. Details below. [Certain] (The first version also listed
  SHOW DRIVES.DMO; that was a virtual-drive artifact, see the correction above.)
- **2 programs need an REU**: WRITEIMAGES2REU/SHOWIMAGESINREU (REU bank 3) and IMG VIEWER.DMO (bank 4). Goldens use a
  512 KB REU (Commodore 1750). No program needs a joystick (FADE.DMO only *optionally* skips with fire). [Certain]
- **New constraint for Ultra:** 14 programs (plus the TSB loader) PEEK/POKE/SYS into TSB's own code and tables at $8000–$BFFF, not only
  the $C000–$CFFF area named in CLAUDE.md (table at the end). Ultra must keep these addresses, or the demos break. [Certain that the programs
  access them; Likely that moving any of them breaks the program.]

## How to run

    make test-demos                                   # all 43 scenarios vs tests/golden (≈ 6 min with 6 VICEs)
    tools/demo_capture.py check mayhem_dmo taco       # selected scenarios
    tools/demo_capture.py capture <id>                # re-record a golden (only on TSB Neo!)
    tools/tsblist.py corpus/tsbneo_260228.d64 "center.dmo"   # TSB-aware listing of a program

Scenarios live in `tests/demos.json`. A checkpoint is reached when the display (screen matrix, colour RAM, bitmap,
RAM charset, VIC mode/colour registers, sprites) has changed after the last input and then stays unchanged for N
frames, with no disk transfer running. "end" also requires BASIC back in its main loop (via the IMAIN vector). This is
event-based, not a frame count, so a slower Ultra can be checked against the same goldens.
Each checkpoint folder holds `screen.txt` (readable), `screen.bin`, `color.bin`, `bitmap.bin` (bitmap mode),
`charset.bin` (RAM charset), `vic.bin`, `sprites.bin` (if any on), `shot.png`; music demos add `sid.bin`
(the sequence of distinct SID register states, one sample per frame).

Input methods: "type" = KERNAL keyboard buffer (GET, KEYGET, FETCH, DO NULL, INPUT). "hold" = key held in the
matrix, for programs that poll `PEEK(197)`/`PEEK(203)` (BLINK, DIGITS, SOUND1, TACO). It is emulated by writing
$C5/$CB right after the KERNAL key scan.

## What does not work even on TSB Neo

1. **DO-TEST.DMO** stops at once with `?BAD MODE ERROR IN 130`. Line 130 is `FETCH "1234567",1,E`, which fetches
   into a *numeric* variable. [Certain: observed.] Cause: TSB's FETCH needs a string variable [Likely]. The header
   says "DO-TEST VON OMEGA", so it probably comes from an older dialect.
   *Update 11 Nov (decision 5, task 1.5):* the original stays as is. A corrected copy,
   `tests/corpus/do-test-fixed.bas` (`FETCH …,1,E$:E=VAL(E$)` on the four FETCH lines, every other byte the original's,
   checked by `tests/corpus_fixed.py`), is scenario `do_test_fixed`. It walks the four menus and quits; borders
   white/violet/orange/brown as chosen. [Certain]
2. ~~SHOW DRIVES.DMO~~ works. *Update 11 Nov:* it is timing-fragile. It checks `ST=-128` exactly, and device 16
   sometimes answers −125, depending on when RETURN is pressed. With RETURN 3 frames later, the released CRT also ends
   with `?DEVICE NOT PRESENT ERROR IN 230`. The scenario presses RETURN one frame after the start screen is stable;
   see reports/1.4-easyflash-crt.md. With VICE's virtual IEC device it stopped at drive 9 with `?DEVICE NOT PRESENT
   ERROR IN 230` (ST was -125, the demo tests `ST=-128`). On the emulated 1541 it scans drives 8–30 and prints
   "1 Drive connected." [Certain] A real C64 should behave like the emulated one [Likely].
3. **OLD-AT.TSB** is a patch for older TSB versions ("TSB ZU ALT!"), meant to be merged into another program. RUN on
   its own, it stops with `?END PROC W/O EXEC ERROR IN 8891`. [Certain: observed. Likely: not meant to run alone.]
4. **IMG VIEWER.DMO** needs an REU: it stages each picture in REU bank 4 (`MEMDEF …,4:MEMSAVE/MEMLOAD`). Without one,
   the picture screen stays blank (bitmap all zero). [Certain: observed both ways.]

Smaller notes:
- WRITEIMAGES2REU lists 7 images; 3 aren't on the disk, and it reports them as not found. [Certain]
- MAYHEM.DMO prints "PRESS ENTER" but simply waits `PAUSE 10`; a key shortens the pause. [Certain]

[Certain] that these accesses exist in the listings. [Likely] the patch points ($8082, $9519, $99CE, $9F22, $A5D7/$A5DB,

## Limits of this baseline

- Timing-dependent output is deliberately not compared (DIGITS, SOUND1, DIRSELECT box, SWITCHSCREEN symbols,
  MULTIMAP jiffies). For those, the checks are: the checkpoints are reached, the expected text appears, and no BASIC
  error shows. [Certain]
- SID traces cover the first 400–1500 frames of each music demo and compare register-state *sequences*, not timing.
  An Ultra that plays the same notes more slowly still matches; one that changes a note does not. Audio output itself
  is not captured. [Certain]
- Not exercised: NEOBLISTER listing a file or printing, EXTINSTALLER actually installing (VDCBASIC needs a C128),
  TSB.MEM/TSB.EXT/TSB.HSG, joystick paths, REU sizes other than 512 KB, more than one drive. [Certain]
- Everything ran in VICE, not on real hardware. [Certain]

## Harness changes made for this task

- `tools/vicemon.py`: VICE binary-monitor client. The old text-monitor approach hung on macOS, because the SDL
  build ignores `quit` from `-moncommands`; that made G0 take ~5 minutes and end in a segfault. Now G0 takes 9 s,
  with no window (`SDL_VIDEODRIVER=dummy`). [Certain on macOS; the Linux headless build is untested with the new driver.]
- `tools/run_crt.sh` keeps its interface and now uses vicemon. `tools/tsblist.py` detokenizes TSB programs.
  `tools/demo_capture.py` is the scenario runner.
- `make test` (G0) is unchanged in scope and passes. `make test-demos` runs this baseline.
