# Task 1.5 — TSB tokenizer collisions (Neo keeps the bug, Ultra fixes it)

Date: 2026-11-11. Decision 6 of 11 Nov: "Neo keeps the ELSEOPEN bug; Ultra fixes it. First list every TSB keyword whose
stored index letter plus following text can be read as a V2 keyword (the general class, not just ELSE+OPEN). Ultra must
produce Neo's exact bytes for every line Neo tokenizes correctly; fixed cases are marked as intended differences."
Labels: [Certain] = run or read here; [Likely] = strong inference; [Guessing] = plausible, unchecked.

## Result

- **The class has 18 keywords and 68 combinations** (table below). Every combination was typed into TSB Neo (released
  CRT, VICE), and Neo stored exactly the bytes in the table. [Certain]
- **Ultra's rule:** after TSB's prefix byte $64, an index byte that is a letter ($41–$5A) is stored as it is. It is
  never the start of a V2 keyword. Everything else is unchanged. [Certain, checked as follows:]
  - **corpus: 1967/1967 lines** tokenize exactly as stored on disk. Neo's own tokenizer gets 1966/1967; the odd line is
    NEO-BLISTER 4685 `…:ELSEOPEN3,3`, and its disk bytes are exactly what Ultra's rule produces.
  - **command suite: 410 lines** (the 21 programs, the corrected DO-TEST and every typed line). Ultra equals Neo on all
    of them except the one deliberate check `100 ifathenprint1:elseopen3,3`.
  - **12,905 lines typed into Neo:** every TSB keyword followed by every V2 keyword, every letter and four statement
    forms, plus every combination below. The Neo mirror (`tools/tsblist.crunch`) gives Neo's bytes for all of them.
    Ultra differs on exactly 112 lines, all inside the class. The data is in `tests/tokenizer/neo_typed.tsv`, checked by
    `tests/crunch_corpus.py` in `make test`.
- **The fixed bytes also work in Neo.** I injected Ultra's bytes for `ELSEOPEN 1,8,15:CLOSE 1:PRINT "OPENED"` into Neo:
  it LISTs as `elseopen 1,8,15…` and runs the OPEN. So a program typed in Ultra and then switched to Neo (GO NEO, or the
  RUN warning) behaves as the user meant. [Certain]
- **What the bug does in Neo** [Certain, run in VICE]:
  - `20 ELSEOPEN 1,8,15` LISTs as `no errorpen 1,8,15` and RUN gives `?SYNTAX ERROR IN 20`;
  - `20 ELSEOK=1` LISTs as `no errork=1` and gives `?SYNTAX ERROR`.

  Other combinations turn into a different TSB command or a placeholder, as the last column shows.

## How it happens

TSB's tokenizer runs first and replaces each TSB keyword by $64 plus the keyword number, a byte from $01 to $7F. Then
the BASIC V2 CRUNCH at $A57C runs over the whole line. It doesn't know about $64, so it reads the number byte as
ordinary text. When that byte is a letter, and the letter plus the next characters spell a V2 keyword, CRUNCH replaces
them with that V2 token. TSB later reads the token EOR $8F as a keyword number. Example: ELSE is number 71 = `G`.
`G`+`O` = GO ($CB), and $CB EOR $8F = 68 = NO ERROR, so `ELSEOPEN` is stored as NO ERROR + `PEN`.

A combination collides only when the text **directly** follows the keyword, with no space or colon. It also needs to
start with the rest of a V2 keyword whose first letter is the index letter, and not be a TSB keyword itself (TSB's pass
takes those first). The following text can be a keyword, a variable name (`ELSEOK=1`) or anything else.

**Which ones matter in practice** [Likely]:
- **ELSE followed by anything starting with O** (`ON`, `OPEN`, `OR`, a variable `O…`), as in crunched code without
  spaces. This is the only one seen in the corpus (NEO-BLISTER).
- **LOCAL** followed by a variable starting with `ND` or `XP`, and **MOBCOL** followed by a variable starting with `ND`,
  `BS`, `TN` or `SC`: possible, rare.
- The rest are commands that take no argument or start with `(`, `:` or a number (DIV, MOD, DUP, D!, INKEY, INST, ON ERROR,
  NO ERROR), or direct-mode commands (AUTO, OLD, TRACE, DUMP, FIND, OPTION, RCOMP). They collide only with odd input.

## Related behaviour that is not a bug (Ultra keeps it)

| Case | What happens | Why it stays |
|---|---|---|
| CLS, X!, MAP (numbers 60–62 = `<`, `=`, `>`) | V2 turns the number byte into an operator token ($B3/$B2/$B1); TSB reads it EOR $8F | Designed in; Ultra must store the same bytes |
| Numbers 42, 43, 45, 47, 63, 94 (`*`, `+`, `-`, `/`, `?`, `^`) | Operator characters, so the table has placeholders (`>`, `>>`) there | No command uses them |
| DO (number 34 = `"`) | V2 sees a quote: the rest of the line after DO is stored as plain text | DO reads it: `DO NULL`, and DONE is DO + plain `NE`. Anything else after DO on that line is skipped (`IF 1 THEN DO:PRINT "IN"` prints nothing, verified). Ultra must keep this or DONE breaks |
| Prefix pairs: LIN+`E` = LINE, DO+`WNB`/`WNW` = DOWNB/DOWNW, MOB+` SET`/`COL` = MOB SET/MOBCOL | TSB's pass takes the earlier, longer keyword | Normal keyword matching, as in V2 |

Not checked: keywords typed with Commodore abbreviations (shifted letters), e.g. `elsE` + shift-O. The V2 abbreviation
rule could create more combinations [Guessing]. Ultra's rule covers them as well, because it never feeds the number byte
to V2 at all.

## Ultra's rule, precisely (for task 4.1)

In the V2 CRUNCH pass:
- if the byte is $64 and the next byte is a letter $41–$5A, or $64 itself (CMOB is number 100 = $64), copy both bytes
  and continue after them;
- every other case is exactly Neo's.

Reference implementation: `tools/tsblist.crunch(text, ultra=True)`. Intended differences from Neo are the lines marked
`fix` in `tests/tokenizer/neo_typed.tsv` and the `INTENDED` set in `tests/crunch_corpus.py`. G4 should compare Ultra's
tokenizer against that file.
