# Task 1.3 — Neo-only detector rules

Date: 2026-11-10. Plan task 1.3 ("Neo-only detector rules, checked against all 39 demos: flags the 19, none of the
other 20"). Reference: `corpus/tsbneo_260228.d64`, TSB Neo 2.60.228. Labels: [Certain] = run or read here;
[Likely] = strong inference; [Guessing] = plausible, unchecked.

## Result

- **The plan's 19 are all flagged, and the base rules flag nothing else: 19 of 39, exactly as planned.** [Certain]
  The plan gives the number, not the names. The 19 are the programs in the address table of
  `reports/1.3-demo-baseline.md` (14 that reach into $8000–$BFFF plus 5 that use TSB's $C000–$CFFF areas), and they are the same 19 the rules find.
- **The U2+ rule N5 flags one more: SWITCHSCREEN.DMO.** It points the screen editor ($0288) and the VIC ($DD00/$D018) at
  the MEM screen at $CC00. In Ultra U2+ that is BASIC workspace, and the MEM screen lives under the I/O chips. So the program
  draws into the wrong memory in Ultra [Likely; untestable until Ultra exists]. The plan foresaw this ("the U2+ extra
  rule may add a few"). **With N5 the verdict is 20 Neo-only and 19 Ultra.** The gate wording for G1/G5 ("the 19 … none of
  the other 20") should become "the 20 … none of the other 19", unless you'd rather keep the MEM screen at $CC00 in
  Ultra (costs 1 KB with MEM on) — see Decision below.
- SHOWIMAGESINREU is **not** flagged, but it does `MEMDEF 1000,$C000,…:MEMLOAD` into hi-res colour data. It runs in Ultra
  only if Ultra's TSB code redirects block-command addresses in $C000–$C3FF (colour data) and $CC00–$CFFF (MEM screen)
  to their new place under I/O. The detector reports this as rule `remap` (no warning). **This is a new requirement for
  task 4.3.** TSBDEMO and IMG VIEWER use the same pattern but are flagged anyway. [Certain that the code is there; Likely
  that remapping is enough.]
- The disk loader `TSB` (not one of the 39) is flagged too, correctly: it POKEs $8082, $C023, $C58C and SYS $C000.
- Checked automatically: `make test` runs `tests/detector.sh` (28 synthetic cases + the expected verdict for each of the 40
  BASIC programs on the disk, from `tests/detector/expected.json`).

## The rules (tools/neodetect.py)

They work on the tokenized program as it sits in memory. Every rule is one a 6502 routine can apply at RUN by walking the
BASIC lines once, with no disk access and no evaluation of expressions. An address counts as "in TSB" when it is in
$8000–$CFFF: the RAM TSB Neo occupies, which Ultra gives to BASIC.

| Rule | Fires on | Why it breaks in Ultra |
|---|---|---|
| N1 | `PEEK`, `POKE`, `WAIT`, `SYS`, `D!PEEK`, `D!POKE`, `MEMPEEK` whose address argument **starts with a literal** in $8000–$CFFF (`POKE $9519,…`, `PEEK($C516)`, `PEEK($9000+I)`, decimal too) | TSB's code, tables, work variables and extension areas are not there in Ultra |
| N2 | TSB `LOAD name,dev,0,addr` with a literal addr in $8000–$CFFF | the file would overwrite BASIC workspace |
| N3 | `SCRLD DEF page,…` with a literal page $80–$CF | same, for SCRLD |
| N4 | a vector in $0300–$0333 set to a literal pointing into TSB: `D!POKE vec,addr` or `POKE vec+1,hi` | jumps into TSB code that isn't there |
| N5 (U2+) | `POKE 648/$0288,hi` with hi $80–$CF (the screen editor writes there), or `POKE $DD00,v` with v AND 3 = 0 (VIC bank 3) | the program draws into $C000–$CFFF itself, where Neo keeps colour data and the MEM screen |
| N6 | `MEMCLR`/`MEMDEF` with a literal C64 address in $8000–$CFFF outside the two remap areas | TSB internals |
| remap | `MEMCLR`/`MEMDEF` into $C000–$C3FF or $CC00–$CFFF | **no warning**: Ultra must redirect these (task 4.3) |
| X | after a literal `POKE 56,hi` (or `D!POKE 55,addr`) with hi ≤ $CF, addresses from that page up to $CFFF are exempt from N1–N3, N5, N6 | the program reserved that memory itself (Ultra-native style), as the plan says |
| i | `LOAD name,dev,1` (target only in the file header) | info only, see open question 1 |

Not looked at: string literals, `REM`, `DATA`. `GO TO` is untouched. Computed addresses (`A=49152:POKE A,0`) are not seen,
hence "seems to". [Certain: synthetic cases `computed_not_seen`, `string_rem_data`, `goto_untouched`.]

How the 20 non-flagged programs were checked beyond the rules: I listed **every** numeric literal in $8000–$CFFF anywhere
in their code and every SYS/USR. The only one is SHOWIMAGESINREU's MEMDEF to $C000 (rule `remap`). I also reviewed all
computed PEEK/POKE targets by hand (DRAW `POKE198`, SHOW DRIVES `POKE186`, SOUND1 `PEEK($A2)`, TACO `PEEK($EB81+X)` and
`POKE $0328,PEEK($0328)±2`, DIGITS `PEEK($CB)`, CHECK-DETECT `MEMCLR $D01E`). None reaches into $8000–$CFFF.
[Certain for the listings; Likely that nothing reaches TSB at run time. There's no dynamic trace yet, see Limits.]

## Synthetic cases (tests/detector/cases.json)

The 28 cases are tokenized with the new `tools/tsblist.crunch`, which mirrors TSB's tokenizer. They pin each rule's edges:
- hex/decimal/parenthesised literals, and leading literal plus offset;
- $7FFF and $D000 as the two sides of the TSB range;
- computed addresses not seen;
- strings, REM and DATA ignored;
- TSB LOAD to $6000 not flagged vs $CB00 flagged;
- `SCRLD DEF $E0` not flagged vs `$CB` flagged;
- vectors to $7000 not flagged vs into TSB flagged;
- `POKE 648,4` vs `648,192`, and VIC bank 0 vs bank 3;
- MEMCLR remap vs `$C500`;
- the MEMTOP exemption, partial and full.

## Decision for you

**D-1.3a: SWITCHSCREEN.** (a) Accept the detector as is: 20 Neo-only, 19 Ultra. SWITCHSCREEN runs after the warning
and switches to Neo. G5 still holds ("all 39 end correct … after the warning"); only the "no warning on the 20" number changes to 19.
(b) Keep the MEM screen at $CC00 when MEM is on, so SWITCHSCREEN's VIC pokes stay valid. That costs 1 KB (50,175 bytes with
MEM on) and breaks the "51,199 with MEM on" promise. **I recommend (a).**

## Open questions for later tasks

1. `LOAD"x",8,1` loads to the address in the file header, which is unknown at RUN. The corpus has none of these except
   the TSB loader. Real-world programs often load machine code to $C000 this way. The cleanest fix is a second check
   at LOAD time (header known) that prints the same warning. This is the plan's open question "warning also at LOAD?",
   and I recommend **yes**, for this case only.
2. The detector must tokenize-compare byte-exactly. TSB stores X!, CLS and MAP (indices 61, 60, 62) as V2 operator
   tokens EOR $8F, and its tokenizer has a real bug: typing `ELSEOPEN` produces `NO ERROR`+`PEN` (see
   reports/1.2-command-suite.md). The ROM detector in task 5.3 reads the stored bytes, so this needs no special handling there.
